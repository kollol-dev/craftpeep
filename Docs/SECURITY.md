# Security and Privacy

Status: threat assessment, 10 November 2026.

Implemented and tested so far: App Sandbox with outgoing network only; https-only fetching with no cookies or cache (T9, T14); response size and item caps (T3); external entities not resolved (T3); feed content reduced to plain text, script and style contents removed (T4); only `http(s)` links stored and re-checked before opening (T5); full-text search input cannot inject query syntax. AI (M4b): models are given no tools; fetched text is sent only as string values inside a JSON document, never in the instructions (T1, tested with an injection fixture); briefing items must cite stories the app supplied or they are dropped; model output is shown as length-capped plain text with no live links; keys are held only in the Keychain and never appear in errors or the ledger (T8, tested); the ledger stores counts, not text; a daily token budget is checked before each call (T16); plain http is allowed only to this Mac. Everything else below is design, not code.

## Assets

| Asset | Where |
|---|---|
| AI and data provider API keys | Keychain |
| Reading behaviour: read, saved, interests, watchlists | Local SQLite |
| Integrity of what the app shows (stories, numbers, AI text) | Store and renderers |
| The user's Mac | Protected by the sandbox and by the app having no code-execution feature |

## Trust boundaries

1. **Network to app.** Every feed, API response and model response is untrusted input.
2. **Retrieved content to model.** Article text is data handed to a model that cannot be relied on to ignore instructions inside it.
3. **Model to app.** Model output is untrusted. It is displayed as text or parsed against a schema, nothing more.
4. **Imported files to app.** Widget specs, OPML and backups from other people.
5. **App to third parties.** What leaves the Mac, and to whom.

## Structural decisions that remove threats

| Decision | Threats removed |
|---|---|
| Widgets are declarative data rendered by app code | Arbitrary code execution through generated or shared widgets |
| No shell, file or command capability exists in the spec or the runtime | Privilege escalation through a widget or a setup file |
| Models have no tools and cannot cause actions | Prompt injection leading to exfiltration or state change |
| The widget builder is never given retrieved content | Injection through headlines into widget generation |
| App Sandbox with network-client and Keychain only | Blast radius of any parser or renderer bug |
| No account, no backend, no telemetry | Server-side breach, tracking |
| No shared API keys in the binary | Key extraction and abuse |

## Threats and mitigations

| # | Threat | Likelihood | Impact | Mitigation | Residual |
|---|---|---|---|---|---|
| T1 | Prompt injection in an article title or excerpt alters a summary or briefing | High (it will be attempted in the wild) | Low to medium: misleading text shown to the user | Delimited untrusted-data section; briefing items must cite known cluster IDs; AI text shown beside the original sources and labelled; no links or images rendered from model output; output length caps | A summary can still be wrong or manipulated. The user can always see the sources. |
| T2 | Injection attempts to make the model leak the system prompt or the user's interests | Medium | Low | Nothing sensitive is in prompts except interest keywords; output goes only to the local UI, never back to the network | Negligible |
| T3 | Malicious feed: oversized payload, deeply nested XML, entity expansion | Medium | Medium: memory or CPU exhaustion | Response size cap enforced while streaming; item count cap; `XMLParser` with external entity resolution left off; parse off the main actor with a time limit; per-source failure isolation | Low |
| T4 | HTML or script in feed content | High | Low given mitigation | Convert to plain text at ingestion; never render feed HTML; no web view in MVP | Low |
| T5 | Dangerous URLs in feeds (`file:`, `javascript:`, custom schemes) | Medium | Medium | Only `http` and `https` are stored; links open in the default browser through the workspace API after scheme re-check | Low |
| T6 | Malicious imported widget spec | Medium once sharing exists | Low: it can only query the store and draw | Full schema and semantic validation on import; expression interpreter with step limit and closed function set (exists); spec size and depth limits; preview before install | Low |
| T7 | A widget with `http` source sends secrets or probes the local network (when that source type is later enabled) | Medium | Medium | HTTPS only; declared hosts approved by the user at install; redirects confined to declared hosts; loopback, link-local and private ranges refused after DNS resolution; `secrets.*` usable only in headers to declared hosts; never generated by the AI builder; secrets are per-widget and excluded from export | Medium. This is why it is deferred. |
| T8 | API key disclosure through logs, crash reports, exports or widget files | Medium | High | Keys only in Keychain; a redacting logger that never formats request headers; exports exclude secrets by construction; keys entered in secure fields | Low |
| T9 | Network attacker tampers with feeds or API responses | Low | Medium | App Transport Security with no exceptions; plain-HTTP feeds refused, with a clear message, unless the user explicitly allows one | Low |
| T10 | Fabricated or stale financial data presented as fact | Medium | High for trust | Provider, timestamp and delay class stored and shown with every figure; no model ever produces a number that is displayed as data; AI text about markets must cite stored figures | Low |
| T11 | Source spoofing: a user-added feed claims to be an official source | Low | Medium | Tier comes from the bundled catalogue keyed by feed URL or is set explicitly by the user; user-added feeds default to unverified; publisher name shown with its host | Low |
| T12 | Tampering with the bundled catalogue or rules | Low | Medium | Shipped inside the signed app bundle; user overrides stored separately and shown as overrides | Low |
| T13 | Local attacker or other app reads the database | Low | Medium (reading behaviour) | Sandbox container; no extra encryption in MVP. State this honestly in the privacy text. | Accepted for MVP |
| T14 | Tracking by feed publishers through per-request identifiers or images | Medium | Low | No images loaded from feeds in MVP; no cookies stored (ephemeral session configuration); generic User-Agent | Low |
| T15 | Malicious backup or OPML import | Low | Medium | OPML parsed with the same limits as feeds; database import validates schema version and runs integrity check before replacing anything; current database kept until import succeeds | Low |
| T16 | Unbounded AI spend through a bug or loop | Medium | Medium (money) | Budget check before every call; ledger; per-feature rate limit; content-hash caching | Low |
| T17 | Supply chain through dependencies | Low | High | One proposed dependency (GRDB), pinned to an exact version and reviewed on update | Low |

## Privacy position

- Local-first, no account, no analytics, no crash reporting service in MVP.
- Outbound connections are limited to: enabled sources, the configured AI provider, the configured market data provider. Settings lists every host contacted and when.
- Sent to an AI provider: public article titles and excerpts, the user's typed prompts, and optionally interest keywords. Not sent: read history, saved items, watchlists, widget layouts.
- Each publisher sees the user's IP address when a feed is fetched, as with any feed reader. This is disclosed.
- Retention defaults: 90 days for unsaved stories, 14 days for fetch logs; both configurable. "Delete all data" removes the database and Keychain items.
- Export produces the user's sources (OPML), saved stories and widget definitions. It never includes secrets.

## Capability model for widgets

| Capability | Granted by | MVP |
|---|---|---|
| Read stories and summaries from the store | Implicit for any installed widget | Yes |
| Read quotes, repositories | Implicit | v0.2 |
| Open a stored article URL in the browser | Implicit; `http(s)` only | Yes |
| Copy text to the pasteboard | Implicit, user-initiated only | Yes |
| Network access to declared hosts | Explicit approval at install | Disabled |
| AI calls | Not available to widgets | Never |
| Files, commands, system data | Not available | Never |

If executable extensions are ever wanted, they belong in a separate process with its own minimal sandbox and a narrow message interface, designed as a new project with its own threat model, not grown out of the widget spec.

## Verification plan

- Fuzz-style fixtures for the feed parser and spec loader (truncated, oversized, deeply nested, wrong encodings).
- Injection fixtures: article excerpts containing instructions, used in validator tests for briefing and builder.
- A test that asserts no log line contains a known fake key after a full ingest-and-summarise run.
- An entitlement check in CI: the built app's entitlements match an allow-list.
- Review of this document at each milestone that adds a data path.
